# Codex 전역 지침

## 응답과 코드 스타일

- 한국어로 답한다. 간략하되 핵심은 완전한 문장으로 설명하고 이모지는 사용하지 않는다.
- 테스트 파일은 사용자가 명시적으로 요청할 때만 생성한다. 기존 테스트와 정적 검사는 변경 범위에 맞게 실행한다.
- 파일 끝에 빈 줄을 추가하지 않는다. ESLint `eol-last`만 해결하기 위한 변경은 하지 않는다.
- 주석과 로그는 한국어로 작성한다. 로그는 한 단어 위주로 작성하고 이모지, 여러 줄, 객체 전체 출력을 피한다.
- 소스 주석은 최소화한다. 코드만으로 알기 어려운 계약, 반환 형태, 예외, 호출 순서 제약만 짧게 적는다.
- 이력, 설계 근거, 대안 비교, 긴 설명은 프로젝트 문서나 `tasks/` 작업 파일에 기록한다.
- 프로젝트의 `AGENTS.md`와 기존 코드 스타일을 따른다. 기존 사용자 변경을 덮어쓰지 않는다.

## 작업 과정

- 모든 요청을 작업 파일로 먼저 등록한다. 작업당 파일 하나를 만들고 `상태: 진행중` 또는 `상태: 완료`를 표기한다.
- 작업 디렉터리가 `~/git` 하위면 프로젝트 루트의 `tasks/`, 그 외에는 `~/tasks/`에 기록한다.
- 파일명은 `YYYYMMDD_HHMMSS_작업내용.md`로 작성한다. 저장소의 파일명 규칙이 있으면 작업내용 부분에 적용한다.
- 타임스탬프는 파일 생성 직전에 아래 명령으로 구한다. 추정하거나 `date` 명령으로 대체하지 않는다.

```bash
python3 -c "from datetime import datetime,timezone,timedelta; print(datetime.now(timezone(timedelta(hours=+9))).strftime('%Y%m%d_%H%M%S'))"
```

- `TASKS.md`는 과거 아카이브이므로 수정하지 않는다. 공용 작업 파일을 계속 갱신하는 방식은 사용하지 않는다.
- 여러 단계가 필요한 작업은 사용 가능한 계획 도구로 관리한다. 도구가 없으면 해당 작업 파일에 진행 상황을 기록한다.
- 한 번에 하나씩 단일 기능을 구현한다. 요청 범위의 조사, 수정, 검증은 완료까지 진행한다.
- 완료 순서는 ① 작업 파일 `상태: 완료`와 요약 작성 → ② 앱 알림 → ③ Git이다.
- 검증 결과와 수행하지 못한 단계는 사실대로 기록하고 보고한다.

## 앱 알림

**설정:** Slack `OFF` / Telegram `ON`

- 완료 메시지는 `mac-m1: [명사요약]` 형식으로 보낸다.
- 두 서비스는 독립적으로 처리한다. 하나가 실패해도 다른 활성 서비스와 Git 단계는 계속한다.
- Codex 전용 알림 도구를 사용한다. 이 도구는 UTF-8 JSON과 `curl`로 전송한다.

```bash
python3 ~/.codex/notify.py --telegram "작업 명사요약"
```

- Slack을 ON으로 바꾸면 위 명령에 `--slack`을 추가한다. OFF인 서비스는 명령에서 제외한다. 둘 다 OFF이면 알림을 생략한다.
- 인증값과 수신 대상은 `~/.codex/notifications.json`에서 읽는다. 해당 파일은 로컬에만 보관하고 Git에 포함하지 않는다.
- 인증값을 응답, 로그, 작업 파일, TIL에 출력하거나 복사하지 않는다.
- 도구나 설정 파일이 없으면 알림 미실행을 보고한다. 다른 프로그램의 설정을 찾아 대체하지 않는다.

## Git 자동화

**설정:** `PUSH` (`PUSH`: add + commit + push / `COMMIT`: commit까지 / `NONE`: 실행하지 않음)

작업 디렉터리가 아래 경로 하위이면 해당 설정으로 대체한다.

| 경로 | 설정 | 사유 |
| --- | --- | --- |
| `~/git/fredit` | `COMMIT` | 사내 저장소, 원격 반영은 사용자가 직접 수행 |
| `~/git/plan_prototype` | `NONE` | Git 작업은 사용자가 직접 수행 |

- 이번 작업의 변경만 스테이징하고 커밋한다. 관계없는 변경이나 인증 파일을 포함하지 않는다.
- 커밋 메시지는 알림과 동일한 명사요약 한 줄로 작성한다. `Co-Authored-By` 등 트레일러는 추가하지 않는다.
- 변경 사항이 없거나 Git 저장소가 아니면 커밋·푸시를 생략하고 이유를 기록한다.
- 사용자가 위 완료 알림과 Git 자동화를 허용했으므로 매번 재확인을 요구하지 않는다. 현재 요청에서 다른 동작을 지정하면 그 요청을 따른다.
- 파일 접근, 네트워크, 승인 정책의 제한은 우회하지 않는다. 실패한 알림이나 푸시는 완료했다고 보고하지 않는다.
